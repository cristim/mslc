# The MSL corpus, taken from indium's test suite. Each .metal file is paired
# with a .metallib that Iridium already translates to GPU-verified SPIR-V, so
# mslc's output has a reference to be compared against.
#
# A second group is the subset of Metal that Blender 4.5.14's
# gpu/metal/mtl_context.mm actually calls through newLibraryWithSource:, frozen
# here verbatim so mslc's progress on real shaders is measured too.
#
# Every entry says what is expected of it, and that is what the corpus test
# asserts:
#
#   expect=valid              the file has to compile to spirv-val-valid SPIR-V.
#                             Not merely to return success: compiling to
#                             something spirv-val rejects fails here too.
#
#   expect=unsupported:WHAT   the file has to fail, and its diagnostic has to
#                             mention WHAT, which is the construct currently in
#                             the way. This is what keeps the list honest in
#                             both directions: a supported fixture cannot stop
#                             compiling unnoticed, and an unsupported one cannot
#                             quietly change what it is blocked on. When a
#                             construct is implemented, the entry that names it
#                             fails until it is edited here to expect=valid,
#                             which is the only way the count moves.
#
# The "N of M compile" line below the table is the measurement. It is expected
# to be below M, and that is not a failure of the test.
